# Strelka — язык конечных автоматов, компилируемый в WebAssembly

**Strelka** («Стрелка») — учебный язык курса «Языковые процессоры
интеллектуальных систем» (ЯПИС). Программа на Strelka описывает автоматы:
состояния, события и переходы-стрелки `Idle -- insert_card -> PinWait`. Компилятор
`fsmc` проверяет граф переходов (опечатки, недостижимые состояния, тупики,
неразобранные события) и генерирует WebAssembly.

Репозиторий — пример того, что сдаётся по лабораторному практикуму: грамматика,
два фронтенда (ANTLR и Lark), семантический анализ, генерация кода, тесты.
Задача взята из карточки «Диалог банкомата» (домен «Конечные автоматы и
протоколы»).

- Разбор на сайте курса: [Пример компилятора: FSM → WASM](https://rserdyukov.github.io/yapis-2026/labs/fsm-compiler/).
- [Playground](https://rserdyukov.github.io/yapis-2026/playground/): этот же
  компилятор работает в браузере через Pyodide.

Имена в коде остались прежними: пакет компилятора — `fsmc`, файлы программ —
`*.fsm`, грамматика — `grammar/Fsm.g4`.

```bash
pip install -r requirements.txt           # antlr4-python3-runtime, lark
./compile.sh examples/atm.fsm scenarios/01_success.events
./compile.sh examples/poker/poker.fsm examples/poker/poker.events  # модули ищутся рядом
python3 -m fsmc examples/puzzle.fsm --emit paths                   # решение головоломки
python3 -m unittest discover -s tests -v  # нужны node и wat2wasm, иначе часть тестов — SKIP
```

## Структура

| Путь | Что |
|---|---|
| `grammar/Fsm.g4` | грамматика ANTLR 4 |
| `fsmc/frontend_antlr/` | ANTLR-фронтенд: `ErrorListener` и `Visitor` → AST; `generated/` — сгенерированный парсер (коммитится) |
| `fsmc/frontend_lark/` | Lark-фронтенд: `fsm.lark` (LALR(1)) и `Transformer` → AST |
| `fsmc/ast.py` | AST, общее для обоих фронтендов |
| `fsmc/semantic.py` | таблицы символов, типы, анализ графа переходов |
| `fsmc/codegen.py` | модель → инструкции WebAssembly |
| `fsmc/wasm.py` | печать инструкций в WAT и двоичный `.wasm` |
| `fsmc/diagram.py` | диаграмма Mermaid |
| `fsmc/web.py` | JSON-мост для playground |
| `runtime/fsm-host.mjs` | хост для Node и браузера; `run.mjs` — запуск сценария в Node |
| `reference/reference.py` | эталон из карточки: оракул для дифференциальных тестов |
| `examples/` | примеры: банкомат, все конструкции языка, задачи ниже |
| `scenarios/` | сценарии событий для банкомата |
| `tests/negative/` | программы, которые не должны компилироваться; `// expect:` — точный набор кодов |
| `tools/gen_antlr.py` | перегенерировать парсер после правки `Fsm.g4` (`--check` — проверить актуальность) |

Два фронтенда нужны, чтобы показать: ANTLR — не единственный способ.
Грамматика, алгоритм разбора и способ построения AST у них разные
(ALL(\*) и Visitor против LALR(1) и Transformer), а результат одинаковый. Выбор
задаётся флагом `--frontend antlr|lark` или переменной `FSMC_FRONTEND`
для `compile.sh`.

## Примеры

| Пример | Что показывает |
|---|---|
| `atm.fsm` | банкомат из карточки задачи; сценарии — в `scenarios/` |

| `abp/` | протокол чередующегося бита: отправитель, получатель, два канала с потерями |

У каждого примера есть `.events` (сценарий) и `.expected` (вывод) — тест
сравнивает их. Оценка покерных рук дополнительно сверяется с эталоном на
Python на 1500 случайных раздачах (`tests/test_poker.py`).

## Расширения языка

Базовый язык — один автомат (`machine`). Поверх него добавлено то, что
обычно ищут в языках общего назначения. Все добавки сохраняют главное
свойство: каждый шаг автомата гарантированно завершается.

| Конструкция | Пример | Аналог |
|---|---|---|
| модуль и импорт | `module cards` … `import cards` … `cards.name(c)` | модули Python/Go |
| чистая функция | `func score(h: int[7], n: int) -> int { ... return s }` | функция без побочных эффектов; её можно звать из guard'а |
| действие как процедура | `action shuffle(var deck: int[52]) { ... }`, вызов `shuffle(deck)` | процедура с параметром по ссылке |
| локальные переменные | `var t: int = deck[i]` | блочная область видимости |
| массивы фиксированной длины | `context { hand: int[7] }`, `const RANKS: string[13] = [...]` | массивы Pascal |
| ограниченный цикл | `for i in 0 .. 52 { ... }` | `for` с вычисленными заранее границами |
| встроенные функции | `len`, `str`, `code`, `chr`, `min`, `max`, `random`, `srand`; `write` без перевода строки; `+` для строк | стандартная библиотека |
| несколько состояний и `any` | `Flop \| Turn -- bet(x) -> ...`, `any -- reset -> Idle`, `Lost -- any ignore` | умолчания у родителя в иерархических автоматах UML |
| параметры автомата | `machine Light(name: string, boss: Watcher) { ... }` | конструктор класса, шаблон |
| интерфейс | `interface Seat { hole(x: int, y: int), act(...) }` | интерфейсы Go: подходит любой автомат с этими событиями |
| система | `system Poker` … `table: Table([you, bot])` … `input you.call` | композиция акторов |
| обмен событиями | `send table.call(me)`, `send seats[i].hole(x, y)`, `send self.next()` | сообщения между акторами (Erlang) |

Как исполняется система. Экземпляры не делят переменных: общаются только
через `send`. Посланное событие встаёт в общую очередь FIFO и
обрабатывается после текущего шага — так причина всегда раньше следствия.
Внешнее событие (из `input`) обрабатывается вместе со всей цепочкой
вызванных им событий. Если автоматы пересылают события бесконечно, после
100 000 шагов выполнение останавливается с ошибкой.

Чего в языке сознательно нет: рекурсии (E133), `while` и присваивания
переменной цикла. Поэтому каждый шаг автомата завершается, а свойства графа
переходов можно доказывать. Индекс массива и переполнение очереди
проверяются при выполнении: хост получает `env.fail` и бросает исключение.

## Семантические проверки

| Код | Уровень | Проверка |
|---|---|---|
| E001 | ошибка | лексическая ошибка |
| E002 | ошибка | синтаксическая ошибка |
| E101 | ошибка | состояние не объявлено (с подсказкой ближайшего имени) |
| E102 | ошибка | состояние недостижимо из начального |
| E103 | ошибка | из состояния нет пути в терминальное |
| E104 | ошибка | событие не объявлено |
| E105 | ошибка | арность или тип образца события не совпадает с объявлением |
| E106 | ошибка | два перехода по одному событию без guard'а |
| W107 | предупреждение | несколько guard'ов без явного порядка `else` |
| W108 | предупреждение | событие не обработано в состоянии и не объявлено `ignore` |
| E109 | ошибка | действие не объявлено |
| E110 | ошибка | имя в выражении не существует |
| E111 | ошибка | guard не `bool` |
| E112 | ошибка | нет начального или терминального состояния, начальных больше одного |
| E113 | ошибка | повторное объявление; имя образца совпадает с полем или константой |
| E114 | ошибка | арность или типы аргументов действия |
| E115 | ошибка | типы: неизвестный тип, несовместимые операнды, присваивание константе или параметру |
| E116 | ошибка | у перехода `a \| b` образцы событий связывают разные имена |
| W117 | предупреждение | переход никогда не сработает: выше стоит переход без guard'а |
| W118 | предупреждение | у всех переходов события есть guard'ы, нет `else` |
| W120 | предупреждение | действие нигде не вызывается |
| E130 | ошибка | модуль не найден, не импортирован, циклический импорт |
| E131 | ошибка | у функции не на всех путях есть `return`; `return` вне функции |
| E132 | ошибка | побочный эффект в `func` или guard'е: присваивание полю, `say`, вызов действия, `send`, `random` |
| E133 | ошибка | рекурсия в графе вызовов функций и действий |
| E134 | ошибка | массивы: индекс не `int`, присваивание массива целиком, литерал вне начального значения |
| E135 | ошибка | `send`: адресат не `self` и не ссылка на экземпляр, у адресата нет события |
| E136 | ошибка | экземпляры в `system`: неизвестный автомат, аргументы, автомат не подходит под интерфейс |
| E137 | ошибка | `any` вместе с другими состояниями или событиями |
| E138 | ошибка | `input` ссылается на несуществующий экземпляр или событие |
| W139 | предупреждение | событие экземпляра никто не посылает и его нет в `input` |

E101–E112 — это строки 1–12 таблицы из раздела 5 карточки задачи.

## Метрики для отчёта (раздел 7 карточки)

| Ошибка `naive.py` | В Python | В FSM | Строк компилятора |
| --- | --- | --- | ---: |
| Опечатка в состоянии | не обнаружена никогда | E101 | 13 |
| Недостижимое состояние | не обнаружена никогда | E102 | 31 |
| Необработанный `timeout` | не обнаружена никогда | W108 | 6 |
| Граница числа попыток | тест, если о нём догадались | остаётся тестом (`scenarios/02`) | — |

Считались непустые строки без комментариев в `fsmc/semantic.py`. Для E102
учтены построение графа (`edges`), обход в ширину (`_bfs`) и цикл проверки.
Для E101 — `_state_ref` и подсказка имени.

## Генерация кода

См. строку документации в `fsmc/codegen.py`. Коротко:

- состояние — `global $state`, поля контекста — `global $ctx_*`;
- событие — экспорт `on_<имя>`, который выбирает ветку через `br_table`;
- строки — `[длина][UTF-8]` в линейной памяти, `$str_eq` и `$alloc` на WAT;
- описание машины — JSON в пользовательской секции `fsm.meta`.

- массивы — в статической области памяти; рекурсии нет, поэтому у каждой
  подпрограммы не больше одной активации и её локальным массивам хватает
  статического кадра;
- экземпляр системы — свои глобальные `$<экз>.state`, `$<экз>.ctx_*` и
  своя копия функций: параметры экземпляра подставляются при компиляции,
  поэтому адресаты `send` известны статически;
- `send` — запись в кольцевую очередь в памяти; `$drain` разбирает её,
  `$dispatch` выбирает обработчик через `br_table`.

Тест `test_encoder_matches_wat2wasm` собирает наш WAT утилитой `wat2wasm` и
требует побайтного совпадения с нашим кодировщиком (без секции `fsm.meta`).
Проверяются все примеры, включая системы.
